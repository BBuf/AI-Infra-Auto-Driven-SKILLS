# October 2026 refresh: evidence scope

This refresh updates all 10 retained skills and the model-history knowledge
base. Source revisions are frozen in
[upstream-source-contracts.md](upstream-source-contracts.md); this date does
not redate historical experiments or certify an installed image.

## Source and catalog coverage

The commit sweep covers the first-parent window after 2026-08-23 through the
frozen heads: SGLang 2,357 commits, vLLM 2,139, TensorRT-LLM 1,149,
TokenSpeed 623 and FlashInfer 706. Current-source inventories separately cover
LLM/VLM fusion, diffusion, stream/collective overlap, graph/launch overhead,
compile passes and runtime controls. Candidate diffs and family-level callers
were inspected; generated CUDA inventories are mechanical extraction, not a
claim that every generated kernel body was read line by line.

The catalogs retain their five-column format. New sections cover GPU idle gaps
and launch overhead, including phase-specific graphs, metadata graphs,
scheduler overlap, replay-stream convergence, PDL, collective dispatch,
symmetric memory and expert-parallel transfer. Historical, removed/reverted,
open/draft and frozen-main families are distinguished. Commit dates are
identified as source dates; API-audited PR rows explicitly record their states.

Consolidation was checked against the final catalogs, then independently
challenged for source paths, symbols, PR states and overbroad dispatch claims.
Qualified symbol checks found no absent current-source qualifiers. Paths that
exist only on an open/draft PR or historical ref are labeled accordingly.
This is coverage of the recorded upstream window and inventories, not proof
that all future or external-package optimizations are known.

FlashInfer main is 0.7.1, whereas inspected SGLang/vLLM dependency pins are
0.7.0.post1. Main-only families and experimental Cake dispatch must not be
presented as available by default in those images.

## Model history and review provenance

There are 118 bilingual history directories: SGLang 45, vLLM 44,
TensorRT-LLM 15 and TokenSpeed 14. The existing 4,085 English PR card entries
remain present; the refreshed inventories contain 5,660 entries. These are
per-document entries, not distinct PRs or independent model validations.
Existing dated manual notes survive regeneration; open-state metadata is
refreshed without silently replacing historical implementation evidence.

New generated entries explicitly identify machine-extracted file/hunk/symbol
inventories and pending manual review. GitHub file API patches can be truncated
or omitted, so their line counts do not establish complete diff review. They
are useful for finding PRs; optimization conclusions require reading the full
diff and current caller. The generator does not fabricate a motivation.

The [TokenSpeed V4.1 history](../model-pr-optimization-history/tokenspeed/deepseek-v41/README.en.md#2026-10-05-manual-diff-review)
contains manual reviews of four complete diffs for schedule reuse, FP8 query preparation
and shape-dependent JIT recompilation. Existing historical review cards retain
their original scope; this refresh does not claim to re-audit every PR.

## Validation and limits

CPU regression tests cover profiler payloads and trace discovery, model
classification and layer boundaries, context-aware compute templates,
standalone skill installation, capacity logs, incident aggregation and
cookbook contracts. Formatting, frontmatter and local links are checked before
submission. The PR records the final test and pre-commit results.

No GPU capture, kernel benchmark or model-accuracy rerun was performed. The
human SGLang review corpus was not recrawled. TokenSpeed HTTP forwarding lives
in external pinned gateway wheels and still requires installed-image checking.
Unknown dense GPU peaks remain unknown; sparse/linear compute templates and
route-dependent expert estimates retain their documented approximations.

## Second source audit and consolidation

Both dedicated SOTA loop skills are removed. Ten task skills and the
model-history knowledge base remain. Profiler guidance is organized by general
principles and operator families: dispatch/numerical rules in `heuristics.md`,
fusion/format eligibility in the existing catalog, and historical manual PR
reviews inside the existing model dossiers. There are no separate V4.1 kernel
optimization reference files.

The second audit re-read source callers, constructors, log schemas and selected
PR diffs/bodies. It found and corrected substantive errors after the first
review:

- Capture helpers now return only the current invocation's labeled stage
  copies; a shared directory with old worker traces no longer masks the new
  prefill/decode captures. A nearer stage label wins over an ancestor label.
- Capacity estimates use one KV head per rank when TP exceeds KV-head count,
  retain draft/Mamba allocations across target-only post-capture resizing, and
  sum target/draft weight deltas. Incident summaries handle phase-keyed graph
  memory and derive request totals from actual running/waiting fields.
- Compute templates distinguish KDA gate topologies, ReLU² shared FFNs,
  overlapping C4 compressors and full-prefill final norms. Kernel-duration
  sums no longer masquerade as elapsed time for whole-pass MFU. Pipeline tools
  require a verified layer count instead of inventing a one-layer model.
- The current KV selector no longer probes FlashMLA reader capability. The
  historical September 22 discussion retains its date; current CUDA/HIP
  eligibility and the separate reader check are stated in the catalog.
- Fusion rows distinguish grouped GEMMs from surrounding quantization/combine
  launches and include missing platform, layout and deferred-finalize guards.
  PR benchmark numbers carry their original workload scope; unscoped probe
  numbers are removed. PDL attribution needs launch/source evidence.
- Fifty conflicting PR date records were checked against GitHub `merged_at`
  in UTC. Their catalog references now use that timestamp instead of mixing
  author dates, committer dates and merge dates.
- The GLM-5.3-Flash B200 FP8 recipe records the upstream selection predicate's
  **in-progress** status; a separate `verified: true` field did not override
  that predicate. The review-corpus description also retains known bot leaks.

These checks combine broad path/symbol inventory with behavioral review of
the changed scripts and selected high-risk catalog rows. They do not establish
exhaustive semantic review of every catalog or generated PR entry. Per-rank
compute ownership remains an explicit TP/EP approximation, and capacity logs
must come from one startup session with ranks separated. No GPU result is
claimed from these CPU/source checks.
