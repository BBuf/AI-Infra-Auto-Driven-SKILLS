# AI-Infra-Auto-Driven-SKILLS v0.1.6

工程地址：[BBuf/AI-Infra-Auto-Driven-SKILLS](https://github.com/BBuf/AI-Infra-Auto-Driven-SKILLS)。

v0.1.6 汇总了 v0.1.5 之后的更新，主要有两部分：

- **新增 `sglang-explainer-video`**：把 SGLang PR 或技术文章做成中文讲解视频。
- **`sglang-humanize-review` 加入维护者现行的 review 标准**：包括 2026 年 kernels/tests 重构后的代码约定，以及 2026-07-27 之后的维护者 review 语料。

这个版本同时配套刚开源的 [SGLang Review Inbox](https://github.com/BBuf/sglang-review-inbox)。它每次 review PR 都使用本仓库 main 上最新的 `sglang-humanize-review`。

当前共 **11 个任务 skill**；模型 PR 历史知识库仍是 **118 份中英双语档案**，本版没有改动。

## 0x2. sglang-humanize-review：按维护者现在的标准 review

v0.1.5 的 review 只依据截至 2026-07-27 的公开语料。之后 SGLang 做了一轮 kernels 和 tests 的重构，维护者的 review 标准也跟着变了。这次把现行标准写进 skill（[PR #128](https://github.com/BBuf/AI-Infra-Auto-Driven-SKILLS/pull/128)）：

- **[`maintainer-standards.md`](https://github.com/BBuf/AI-Infra-Auto-Driven-SKILLS/blob/v0.1.6/skills/sglang-humanize-review/references/maintainer-standards.md)（必读）**：
  - review 的顺序，改动范围要小；
  - 重构后代码应该放在哪里；
  - 不新增 flag 和环境变量，优先自动分发；
  - 测试必须真正走到改动的路径，而且值得长期保留；
  - PR 描述需要附带的证据、合并标准，以及评论怎么写。

  它和旧语料里的先例冲突时，以它为准。
- **[`refactor-conventions.md`](https://github.com/BBuf/AI-Infra-Auto-Driven-SKILLS/blob/v0.1.6/skills/sglang-humanize-review/references/refactor-conventions.md)**：从 60 个已合并的重构和清理 PR 中整理出 30 条可执行的规则。规则覆盖 kernels 命名空间和分组、`KernelSpec`、`BaseFusedOp`、gate 与 launcher 的分工、MoE router、diffusion facade 和融合层级、测试布局与 CI lane、环境变量、死代码等。每条都附上对应的 diff 特征，以及违反时会失败的守卫测试。
- **维护者近期 review 语料**（`bbuf-recent-review-corpus.jsonl.gz`）：466 个 review episode，包含 526 条维护者评论，覆盖 204 个公开 PR，时间范围是 2026-07-27 至 2026-10-30。格式与主语料相同，`summarize_sglang_review_corpus.py --corpus` 可以直接使用。已排除自动预审评论、斜杠命令、只有 approve 没有内容的记录，以及涉及未发布模型或私有项目的 PR。
- **[`bbuf-review-patterns.md`](https://github.com/BBuf/AI-Infra-Auto-Driven-SKILLS/blob/v0.1.6/skills/sglang-humanize-review/references/bbuf-review-patterns.md)**：常见关注点及出现次数、示例评论，以及评论的语气习惯。
- **`SKILL.md`**：新增「必读文件」一节，工作流里加入对补充语料的检索，并补充：
  - 按标准逐项检查的要求；
  - 评论写法；
  - 重构后新目录结构的路径别名；
  - 语料截止时间的说明。

使用时，旧语料提供的是「这个子系统以前出过什么问题」的线索；判断标准以 `maintainer-standards.md` 和当前源码为准。

## 0x3. 新增 sglang-explainer-video

[`sglang-explainer-video`](https://github.com/BBuf/AI-Infra-Auto-Driven-SKILLS/tree/v0.1.6/skills/sglang-explainer-video)（[PR #101](https://github.com/BBuf/AI-Infra-Auto-Driven-SKILLS/pull/101)）接收一个 SGLang PR 编号或链接，或者一篇 Markdown 文章，产出 1920×1080 的中文讲解视频，同时生成一张封面图和一张 B 站封面，统一放到 `~/Desktop`。它基于 HyperFrames 的 pr-to-video 流程（固定版本），补上了中文场景需要的修复。

- **讲透内容**：讲清每个算法和每处代码改动，视频时长跟着内容走，不设上限。
- **流程**：读源材料 → 写故事和脚本 → edge-tts 晓晓配音（带逐词时间戳）→ 视觉设计 → 封面 → 中英双语字幕 → 最多 5 个 frame worker 并行出帧 → 检查和渲染 → 逐帧 QA → 交付。
- **英文术语读得准**：`pronunciation.json` 只改写配音听到的读法，字幕保留原文。目前有 68 个词条、17 条模式规则、32 个缩写。`pron_check` 检查读音，`poly_probe` 处理中文多音字。每做一个视频，发现读错的词都要补回词库。v0.1.5 之后的 26 次后续更新（#102–#127）大多来自实际视频里暴露的读音和字幕问题。
- **品牌和主题**：
  - 默认使用 SGLang 品牌橙；也有 `kimi-dark` 主题。
  - 讲其他项目时不使用 SGLang 的品牌元素。
  - 每个视频的最后一帧都带「关注 SGLang」条。
  - B 站封面用 `--png-bili` 按 1440×1080 安全区单独渲染。
- **改配音**：`revoice.sh` 可以给已完成的视频重新配音。旧状态先备份，原视频不会被覆盖。
- **发布**：只有用户明确要求时才按 [`publishing.md`](https://github.com/BBuf/AI-Infra-Auto-Driven-SKILLS/blob/v0.1.6/skills/sglang-explainer-video/references/publishing.md) 发布到 B 站和小红书。
  - 小红书笔记必须标记 SGLang 官方账号，正文里不要 @。
  - 两个平台都要声明含 AI 生成内容。
  - 要上传的文件由用户自己在系统对话框里选择。

第一次使用前先运行 `scripts/setup_env.sh`，需要 Node 22、ffmpeg 和 Chrome。脚本会准备固定版本的 HyperFrames 和字幕补丁、edge-tts 环境和 Noto 中文字体。

## 0x4. 配套项目：SGLang Review Inbox

[BBuf/sglang-review-inbox](https://github.com/BBuf/sglang-review-inbox) 是一个跑在本机的网页，把别人请你 review 的 SGLang PR 收集起来，交给 coding agent 跑完整个流程。PR 来源包括 Slack 的 @、私信、PR 频道，以及 GitHub 上 @你或指派给你的 PR。流程包括：

- review 和独立复核；
- 跟进 CI，和作者来回讨论；
- approve 和合并；
- 在原 Slack 线程里回一句结果。

需要维护者亲自看的只留下高风险的 PR。

它和本仓库的关系：

- 每次 review 都使用本仓库 main 上最新的 `sglang-humanize-review`（每 10 分钟同步一次）。
- review 结束后检查命令日志：没读 `SKILL.md`、没读 `maintainer-standards.md`、没检索主语料或维护者近期语料的 review 一律作废重跑。
- 已经 review 过的 PR 推了新代码，只做增量复审：只看新改动，并复查之前提出的问题。

部署方式见它的 [README](https://github.com/BBuf/sglang-review-inbox#readme)。

## 0x5. 安装 v0.1.6

`v0.1.6` 是本次仓库发布的 tag；Claude Code 插件配置里的版本号保持 `0.10.0`。

下面的命令新建一个独立的 v0.1.6 checkout，并把当前所有 skill 链接到所选运行环境的目录：

```bash
git clone --branch v0.1.6 https://github.com/BBuf/AI-Infra-Auto-Driven-SKILLS.git AI-Infra-Auto-Driven-SKILLS-v0.1.6
cd AI-Infra-Auto-Driven-SKILLS-v0.1.6

# Codex；使用 Claude Code 时改为 "$HOME/.claude/skills"
SKILL_DIR="${CODEX_HOME:-$HOME/.codex}/skills"
mkdir -p "$SKILL_DIR"
for d in skills/*/ skills/model-optimization/*/; do
  [ -f "$d/SKILL.md" ] || continue
  ln -sfn "$PWD/${d%/}" "$SKILL_DIR/$(basename "$d")"
done
ln -sfn "$PWD/model-pr-optimization-history" "$SKILL_DIR/model-pr-history-knowledge"
```

从 v0.1.5 升级时，在原来的 checkout 里切到 `v0.1.6` 即可，已有的链接仍然有效；新增的 `sglang-explainer-video` 需要再跑一遍上面的链接循环。

安装后按任务调用对应名称，例如：

> 使用 sglang-humanize-review review sgl-project/sglang#&lt;编号&gt;。先读 maintainer-standards.md 和 refactor-conventions.md，再检索主语料和维护者近期语料，每个问题都回到当前 head 的源码核对。

> 使用 sglang-explainer-video，把 sglang PR &lt;编号&gt; 做成中文讲解视频。
