# AI-Infra-Auto-Driven-SKILLS v0.1.5

工程地址：[BBuf/AI-Infra-Auto-Driven-SKILLS](https://github.com/BBuf/AI-Infra-Auto-Driven-SKILLS)。

v0.1.5 汇总了 v0.1.0 之后的更新。这个版本新增 SGLang 模型 Day-0 支持和 Torch Profiler 层标记工具，把模型 PR 历史扩展到 SGLang、vLLM、TensorRT-LLM、TokenSpeed 四个框架，并按 2026-10-05 固定的上游源码版本更新了 benchmark、profile、容量分析和计算量估算流程。

当前保留 **10 个任务 skill**，另有一份包含 **118 份中英双语模型档案**的 PR 历史知识库。两个独立的 SOTA loop skill 已移除；性能优化仍可组合使用 benchmark、profiler、pipeline analysis、compute simulation 和 PR history。

## 0x2. 新增 Day-0 支持和 trace 层导航

### SGLang 模型 Day-0 支持

[`sglang-model-day0-support`](https://github.com/BBuf/AI-Infra-Auto-Driven-SKILLS/tree/v0.1.5/skills/model-optimization/sglang-model-day0-support) 用来拆解新模型接入任务：先固定模型、权重、框架和依赖版本，再对照已有实现列出缺口，组织有依赖关系的 PR，逐项验收。

它提供可复制的文档模板，覆盖 scope contract、architecture gap map、PR DAG、validation matrix、release lock 和后续任务记录。检查范围包括权重加载、协议输出、cache/state、并行拓扑、量化、推测解码、多模态和专用 kernel 的 fallback。参考案例包含 DeepSeek-V4/V4.1 和 Kimi K3。

使用时要明确哪些能力是 Day-0 必须交付的，哪些属于后续修复或性能优化；每项完成结论都要有对应的代码版本和验证证据。

### Torch Profiler 层标记和紧凑视图

[`torch-profiler-layer-track`](https://github.com/BBuf/AI-Infra-Auto-Driven-SKILLS/tree/v0.1.5/skills/torch-profiler-layer-track) 为已有 Chrome JSON trace 添加层导航辅助轨道。先从模型配置、源码调用点和 kernel cadence 确认层数及起点，再生成 L0/L1/... 标记，支持区分 target verify 和 draft pass。

对于 CUDA Graph 导致的大量 GPU stream 显示行，工具可以生成紧凑视图，把非重叠活动放进可复用的显示轨道，并保存原始轨道映射。kernel 名称、时间戳、时长和原始 stream 信息保留，输入 trace 也保留。

这些标记表示 anchor 之间的导航区间，不能直接当作完整层耗时；紧凑轨道只改变显示方式，不代表减少了运行时 CUDA streams 或提升了执行性能。

## 0x4. 更新采集接口，修正分析口径

这次源码核对覆盖 SGLang、vLLM、TensorRT-LLM、TokenSpeed 和 FlashInfer。固定的 commit 和对应接口记录在 [upstream-source-contracts.md](https://github.com/BBuf/AI-Infra-Auto-Driven-SKILLS/blob/v0.1.5/docs/upstream-source-contracts.md)。主要变化包括：

- **Benchmark**：更新 serving 参数与 cookbook 配置，保留同模型、同精度、同 GPU 预算、同 workload 和 SLA 的比较约束；上游标为进行中的 recipe 会保留该状态。
- **Profiler**：核对各框架的启动配置、运行时采集接口和输出命名。采集助手只返回本轮产生的 stage trace，避免把共享目录里的旧文件当成新结果；TokenSpeed 外部 gateway 的转发行为仍需在实际镜像中确认。
- **Fusion / overlap**：补充图执行、launch overhead、通信与计算重叠、量化和 collective fusion 等目录内容，并标明调用条件、平台、dtype、layout 和历史状态。上游 main 中存在某段代码，不代表当前安装包或模型一定调用它。
- **容量分析**：修正 TP 大于 KV-head 数时的估算，处理 post-capture 容量调整、draft/Mamba 分配及 target/draft 权重增量，按同一次启动的 rank-local 日志解释显存。
- **计算量与 MFU**：细化 MLA、MoE、压缩 attention、KDA 和 shared FFN 等模板；整段 forward 的 MFU 使用实际 elapsed time，避免把存在重叠的 kernel 时长求和当作墙钟时间。
- **Pipeline 和 incident**：层划分需要已确认的层数；故障汇总适配按阶段记录的 graph memory，并从实际 running/waiting 字段计算请求总数。

SGLang review 语料也已从 v0.1.0 时的 2024–2025 范围更新至 **2026-07-27**，包括公开的 inline threads、PR comments 和 review submissions，保留原始多语言文本。10 月这次源码更新没有重新抓取该语料，过滤后也仍有已知 bot 残留；使用时需要结合上下文和当前代码判断。

## 0x5. 统一优化原则和目录

DeepSeek-V4.1 调研中可复用的优化原则已合并到 profiler 的通用文档：dispatch 和数值约束放在 `heuristics.md`，fusion、格式与调用条件放在现有 catalog，具体 PR 的历史分析放回模型档案。

原先独立的 `dsv41-kernel-optimization.md`、`dsv41-mhc-fusions.md`、`dsv41-upstream-kernels.md` 已移除。后续分析其他模型时也使用同一套原则，并核对实际调用路径。

以下两个独立 skill 也已移除：

- `sglang-sota-humanize-loop`
- `vllm-sota-humanize-loop`

如果之前手动复制或链接安装过它们，升级时应移除对应的旧安装项，并更新自己的任务 prompt。新的安装循环只安装当前存在的 skill，不会自动清理旧副本或失效链接。

Diffusion 的逐模型和组件优化流程保留在 [`sglang-diffusion-optimization-flows/`](https://github.com/BBuf/AI-Infra-Auto-Driven-SKILLS/tree/v0.1.5/sglang-diffusion-optimization-flows)，目前是 workflow 草稿，供结合实际 benchmark/profile 使用。

## 0x6. 安装 v0.1.5

`v0.1.5` 是本次仓库发布的 tag；Claude Code 插件配置中的现有版本号保持 `0.8.0`。

下面的命令创建独立的 v0.1.5 checkout，并把当前 skill 链接到所选运行环境的目录：

```bash
git clone --branch v0.1.5 https://github.com/BBuf/AI-Infra-Auto-Driven-SKILLS.git AI-Infra-Auto-Driven-SKILLS-v0.1.5
cd AI-Infra-Auto-Driven-SKILLS-v0.1.5

# Codex；使用 Claude Code 时改为 "$HOME/.claude/skills"
SKILL_DIR="${CODEX_HOME:-$HOME/.codex}/skills"
mkdir -p "$SKILL_DIR"
for d in skills/*/ skills/model-optimization/*/; do
  [ -f "$d/SKILL.md" ] || continue
  ln -sfn "$PWD/${d%/}" "$SKILL_DIR/$(basename "$d")"
done
ln -sfn "$PWD/model-pr-optimization-history" "$SKILL_DIR/model-pr-history-knowledge"
```

也可以只复制或链接所需的 skill。安装后按任务调用对应名称，例如：

> 使用 torch-profiler-layer-track 为这份 trace 添加层导航。先核对模型层数、target/draft 阶段和每层 anchor，再生成紧凑视图，保留原始 trace 和映射报告。

> 使用 sglang-model-day0-support，基于公开模型配置和当前 SGLang 源码，整理支持范围、架构缺口、PR 依赖图和验证矩阵。

## 0x7. 验证记录

发布前的 CPU 回归测试为 **235 passed**，覆盖采集参数、trace 发现、模型分类、层边界、计算模板、容量日志、incident 汇总、Day-0 模板和 PR 历史生成等工具。格式与本地文档链接检查通过。

本次源码刷新没有重新执行 GPU capture、kernel benchmark 或模型精度测试。性能数字仍以各自原始实验的模型、硬件、精度、workload 和版本为准；计算模板中有关稀疏/线性结构及 TP/EP 分摊的近似也继续保留。
